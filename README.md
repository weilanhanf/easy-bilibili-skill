# Easy-Bilibili-Skill

> B站个人视频知识库 - 一个专为B站收藏智能检索设计的 AI Skill 项目

## 📖 项目简介

本项目是一个完整的 B站个人收藏检索解决方案，包含：

- **核心 Skill**：`.agent/skills/easy-bilibili` - 智能收藏检索助手
- **同步脚本**：`scripts/` - Cookie 验证、数据同步工具
- **知识库**：`knowledge/` - 1400+ 视频文档的结构化存储
- **最佳实践**：触发条件验证、分层索引、精准检索

### 核心特性

✅ **精准触发** - 必须包含"B站/哔哩哔哩"关键词才执行  
✅ **分层索引** - 通过 `data_structure.md` 智能导航收藏夹  
✅ **组合检索** - 使用正则表达式精准匹配主题  
✅ **执行透明** - 先输出执行步骤，再给出结果  
✅ **友好提示** - Cookie 过期、反爬触发等异常场景清晰指引

### 第一步：配置 Cookie（必须）

**为什么需要 Cookie？**

B站的收藏夹、观看历史等个人数据需要登录才能访问。本项目通过 Cookie 模拟登录状态获取数据。

**Cookie 包含什么？**

| 字段 | 用途 | 必需 |
|------|------|------|
| `SESSDATA` | 登录凭证，验证身份 | ✅ 必须 |
| `bili_jct` | CSRF Token，防止跨站攻击 | ✅ 必须 |
| `buvid3` | 设备指纹 | 推荐 |
| `buvid4` | 设备指纹v4 | 推荐 |
| `DedeUserID` | 用户ID | 推荐 |

**获取完整 Cookie 步骤**：

1. **登录 B站**
   - 打开浏览器访问 [bilibili.com](https://www.bilibili.com)
   - 使用你的账号登录

2. **打开开发者工具**
   - 按 `F12`（或右键 → 检查）
   - 切换到 **Network**（网络）标签

3. **获取 Cookie**
   - 刷新页面（`F5`）
   - 在请求列表中点击任意请求
   - 在右侧 **Headers** → **Request Headers** 中找到 **Cookie**
   - 复制整行 Cookie（右键 → Copy value）

4. **运行配置脚本**
   ```bash
   python scripts/login.py
   ```
   - 按提示粘贴完整 Cookie
   - 脚本会自动验证并保存到 `config.json`

**配置文件示例**：

```json
{
  "user_id": 309534098,
  "user_name": "你的用户名",
  "cookie": "SESSDATA=xxx; bili_jct=xxx; buvid3=xxx; ...",
  "last_sync": null
}
```

## ⚠️ Cookie 有效期与更新说明

### Cookie 会过期吗？

**是的，Cookie 会过期。**

| 字段 | 有效期 | 说明 |
|------|--------|------|
| `SESSDATA` | **约 30 天** | 主登录凭证，会自然过期 |
| `bili_jct` | 随 SESSDATA | 与登录状态同步 |
| `buvid3/buvid4` | 长期 | 设备指纹，相对稳定 |

### 什么情况会导致 Cookie 失效？

| 情况 | 说明 |
|------|------|
| 自然过期 | 约 30 天后自动失效 |
| 其他设备登录 | 在另一台设备登录会使旧 Cookie 失效 |
| 修改密码 | 修改密码后 Cookie 立即失效 |
| 退出登录 | 主动退出登录后 Cookie 失效 |

### Cookie 失效后会发生什么？

当你尝试同步数据时，会看到以下提示：

```
==================================================
[ERROR] 同步失败
==================================================

错误类型: Cookie 已过期

可能原因:
  1. Cookie 有效期约 30 天，已自然过期
  2. 账号在其他设备登录导致 Cookie 失效
  3. 修改密码或退出登录

解决建议:
  1. 重新登录 bilibili.com
  2. 获取新的完整 Cookie
  3. 运行 python scripts/login.py 更新配置

下一步操作: 更新 Cookie: python scripts/login.py

更多帮助: docs/troubleshooting.md
==================================================
```

### 如何更新 Cookie？

**步骤一：重新获取 Cookie**

1. 打开浏览器，访问 [bilibili.com](https://www.bilibili.com)
2. 使用你的账号登录
3. 按 `F12` 打开开发者工具
4. 切换到 **Network**（网络）标签
5. 刷新页面（`F5`）
6. 点击任意请求 → **Headers** → **Request Headers**
7. 找到 **Cookie**，复制整行内容

**步骤二：更新配置**

```bash
python scripts/login.py
```

按提示粘贴新的 Cookie，脚本会自动验证并更新配置。

**步骤三：验证更新成功**

```bash
python scripts/login.py --check
```

看到 `[OK] Cookie 有效` 即表示更新成功。

### 建议：定期更新

| 建议频率 | 说明 |
|----------|------|
| 每 25 天 | 提前更新，避免过期影响使用 |
| 收藏变动后 | 确保同步前 Cookie 有效 |
| 同步失败时 | 首先检查 Cookie 是否过期 |

## 🎯 核心设计理念

### 1. 精准触发条件

**避免误触发**：只有明确包含以下关键词才执行：

| 触发方式 | 示例 |
|----------|------|
| 斜杠命令 | `/easy-bilibili` |
| 明确前缀 | `B站搜索xxx`、`我的B站收藏xxx` |

**不触发的情况**：
- ❌ "西安美食有哪些"（缺少 B站 关键词）
- ❌ "面试视频推荐"（未指定来源）

### 2. 组合关键词检索

**核心原则**：使用组合正则精准匹配，而非单一宽泛关键词

| 用户问题 | 正确做法 | 错误做法 |
|----------|----------|----------|
| B站收藏的西安美食 | `西安.*美食` | ❌ 仅 `西安` |
| B站收藏的Java教程 | `Java.*教程` | ❌ 仅 `编程` |

### 3. 执行步骤透明

每次执行前先输出执行计划：

```
========================================
📋 执行计划
========================================
1. [验证] 检查触发条件是否满足
2. [导航] 读取索引了解结构
3. [检索] 精准搜索视频文档
4. [输出] 结构化展示结果
========================================
```

### 4. 渐进式检索

**多轮迭代机制（最多 3 轮）**：

| 轮次 | 策略 | 操作 |
|------|------|------|
| 1 | 精准匹配 | 组合关键词搜索 |
| 2 | 放宽条件 | 去除部分限定词 |
| 3 | 分类筛选 | 指定收藏夹内搜索 |

## 📋 最佳实践

### ✅ 推荐做法

1. **使用明确前缀**：`B站搜索 [关键词]`
2. **提供具体主题**：`B站收藏的西安美食`（而非"西安"）

2. ❌ 使用单一宽泛关键词搜索
3. ❌ 频繁同步（可能触发反爬）
4. ❌ 期望实时更新（数据是快照，非实时）

## 🔧 故障排查

| 错误 | 原因 | 解决方案 |
|------|------|----------|
| HTTP 412 | 触发反爬 | 等待 30 分钟后重试 |
| Cookie 无效 | 已过期 | 运行 `login.py` 更新 |
| 无数据 | 未同步 | 运行 `sync.py` 初始化 |
| 结果太多 | 关键词太宽 | 使用更具体关键词 |
| 结果不准 | 单关键词 | 组合多个关键词 |

详见：`docs/troubleshooting.md`

## 💡 常见问题

### Q1: 为什么搜索结果不准确？

**A**: 可能使用了单一宽泛关键词。建议：
- 使用组合关键词：`西安美食` 而非 `西安`
- 指定收藏夹：`java收藏夹中的面试视频`

### Q2: 多久需要同步一次？

**A**: 按需同步，而非定时同步：
- 收藏变动后手动同步
- Cookie 过期时先更新再同步
- 避免频繁同步触发反爬

### Q3: 如何获取完整 Cookie？

**A**:
1. 登录 bilibili.com
2. F12 → Network → 刷新页面
3. 点击任意请求 → Headers → Cookie
4. 复制整行（包含所有字段）

### Q4: 可以搜索其他人的收藏吗？

**A**: 不可以。只能检索自己的收藏数据。

| 观看状态筛选 | `B站收藏中未看的视频` | 返回所有未看视频 |
| 同步请求 | `同步我的B站收藏` | 执行 sync.py 并返回结果 |

## 🔮 后续优化方向

### 1. 向量检索（语义搜索）

当前使用关键词搜索，后续可引入向量检索实现语义搜索：

| 对比 | 关键词搜索（当前） | 向量检索（优化后） |
|------|-------------------|-------------------|
| 搜索方式 | 精确匹配关键词 | 语义相似度匹配 |
| 示例 | 搜索"味道"只能匹配"味道" | 搜索"味道"能匹配"口感"、"风味" |
| 依赖 | 无 | Embedding模型（如 DashScope） |
| 存储 | Markdown文件 | ChromaDB/本地向量库 |

**实现方案**：
- 使用 DashScope Embeddings API 或本地模型（text2vec-chinese）
- 字幕按时间分块（30秒或100字/块）
- 为每块生成向量，存入 ChromaDB

### 2. ASR 音频转写（无字幕视频兜底）

当前只能获取有字幕的视频（约 67% 覆盖率），后续可引入 ASR 实现 100% 覆盖：

| 方案 | 覆盖率 | 成本 | 说明 |
|------|--------|------|------|
| B站字幕API（当前） | ~67% | 免费 | 仅获取有字幕的视频 |
| DashScope ASR | 100% | 按时长收费（约0.02元/分钟） | 音频上传到阿里云识别 |
| OpenAI Whisper | 100% | 按时长收费 | 类似 DashScope |

**ASR 工作流程**：
```
无字幕视频 → 下载音频流 → 上传 DashScope → 语音识别 → 返回文字 → 存入知识库
```

**费用估算**：
- 1000 分钟视频 ≈ 20 元
- 需要：阿里云账号 + DashScope API Key

**参考项目**：[bilibili-rag](https://github.com/via007/bilibili-rag)
