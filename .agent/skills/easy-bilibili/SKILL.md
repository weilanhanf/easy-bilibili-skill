# B站个人视频知识库检索 Skill（easy-bilibili）

## 知识库结构说明

```
knowledge/
├── data_structure.md     # 根索引：总体概览
├── folders.md             # 收藏夹详细列表
├── videos/                # 视频文档目录（1400+文件）
│   ├── BV1xxx.md
│   └── ...
└── followings/            # 关注UP主文档目录
    ├── data_structure.md  # 关注列表索引
    ├── up_123456.md       # UP主详情
    └── ...
```

- **分层索引**：通过 `data_structure.md` 了解目录结构，避免盲目搜索
- **视频文档**：1400+ 文件，每个约 30-50 行
- **UP主文档**：关注列表，每个约 20-30 行

### ✅ 触发条件

| 条件 | 示例 |
|------|------|
| 斜杠命令 | `/easy-bilibili` |

| 关注相关 | `B站关注xxx`、`我的B站关注`、`我关注的UP主` |

### ❌ 不触发

| 示例 | 原因 |
|------|------|

| "面试视频推荐" | 未指定 B站收藏来源 |

**验证结果**：满足条件 → 继续执行；不满足 → 告知用户正确的提问方式

## 功能分类处理

根据问题类型，选择不同的处理流程：

### 1. 收藏视频检索

**触发关键词**：`收藏`、`B站搜索`

```
========================================
📋 执行计划
========================================
1. [验证] 检查触发条件是否满足
2. [导航] 读取 data_structure.md 了解收藏夹结构
3. [定位] 根据问题关键词锁定目标收藏夹
4. [检索] 使用精准正则表达式搜索视频
5. [输出] 结构化展示结果
========================================
```

### 2. 关注UP主查询

**触发关键词**：`关注`、`UP主`

```
========================================
📋 执行计划
========================================
1. [验证] 检查触发条件是否满足
2. [导航] 读取 followings/data_structure.md 了解关注列表
3. [检索] 根据关键词搜索UP主
4. [输出] 结构化展示结果
========================================
```

**支持的问题类型**：

| 问题类型 | 示例 |
|----------|------|
| 统计 | "我的B站关注了多少UP主？" |
| 搜索 | "我关注中有没有做美食的UP主？" |
| 详情 | "我关注的xxx UP主粉丝数是多少？" |
| 列表 | "我的B站关注列表" |

### 3. 同步请求

**触发关键词**：`同步`、`初始化`、`更新数据`、`刷新`

**用户自然语言请求 → AI 自动执行**：

| 用户说 | AI 执行操作 | 说明 |
|--------|-------------|------|
| "同步我的B站收藏" | 运行 `scripts/sync.py` | 自动执行，无需用户操作 |
| "更新这些视频的统计" | 运行 `scripts/enrich_stats.py` | 补充缺失数据 |
| "同步我的B站关注" | 运行 `scripts/sync_followings.py` | 基础信息 |
| "同步关注的完整信息" | 运行 `scripts/sync_followings.py --full` | 含粉丝数等 |

**交互原则（重要）**：

1. **触发条件必须包含B站关键词** — 必须包含 `B站`、`bilibili`、`哔哩哔哩`、`我的收藏` 等关键词
2. **禁止提示用户手动执行脚本** — ❌ 不要说"请运行 python scripts/sync.py"
3. **自然语言交互** — ✅ 用户说"同步我的B站收藏"，AI 直接执行并返回结果
4. **主动询问** — 发现数据缺失时，询问用户是否需要更新：
   > "部分视频数据不完整，是否现在更新？"
5. **执行透明** — 执行前简要说明操作，执行后展示结果摘要

**执行流程**：

```
用户: "同步我的B站收藏"          ← 包含"B站"关键词，触发
    │
    ▼
AI: "正在同步您的B站收藏数据..."
    │
    ▼
[执行 scripts/sync.py]
    │
    ▼
AI: "同步完成！已更新 1459 个视频，获取完整统计数据。"
```

**不触发的情况**：

```
用户: "同步我的收藏"             ← 缺少B站关键词，不触发
AI: "请问您指的是哪个平台的收藏？B站收藏请说'同步我的B站收藏'"

用户: "更新数据"                 ← 缺少B站关键词，不触发
AI: "请问您要更新什么数据？B站收藏请说'更新我的B站收藏数据'"
```

**警告**：完整模式会对每个UP主发起单独请求，391个UP主≈391次请求，可能触发HTTP 412反爬机制。建议：
- 非高峰时段执行
- 不要频繁执行
- 首次同步使用基础模式即可

## 收藏视频检索流程

### 步骤详解

#### 1. 验证触发条件

- 检查用户问题是否包含触发关键词
- 不满足时提示正确用法：
  > 请使用以下格式提问：
  > - `B站搜索 [关键词]`
  > - `我的B站收藏中关于 [主题] 的视频`

#### 2. 分层索引导航

- 读取 `knowledge/data_structure.md`（limit=100）
- 了解收藏夹分类和视频分布
- 根据问题主题锁定相关收藏夹

#### 3. 精准检索策略

| 用户问题 | 检索策略 | 说明 |
|----------|----------|------|
| `B站收藏的西安美食` | `西安.*美食 \| 美食.*西安` | 主题交叉，精准匹配 |
| `B站收藏的面试视频` | `面试` | 单一主题，直接匹配 |
| `B站收藏的Java教程` | `Java.*教程 \| 教程.*Java` | 技术主题限定 |
| `B站收藏的乒乓球教学` | `乒乓球.*教学` | 运动+限定词 |

**关键词选择原则**：
- 从用户问题提取 2-5 个核心关键词
- 组合正则表达式，确保同时匹配多个概念
- 避免单一宽泛关键词（如仅用"西安"）

#### 4. 渐进式检索

**多轮迭代机制（最多 3 轮）**：

| 轮次 | 策略 | 操作 |
|------|------|------|
| 1 | 精准匹配 | 使用组合关键词搜索 |
| 2 | 放宽条件 | 去除部分限定词重试 |
| 3 | 分类筛选 | 在指定收藏夹内搜索 |

**终止条件**：
- 找到足够信息 ✅
- 达到 3 次尝试 ⏱️
- 结果为空时明确告知

#### 5. 智能信息分层与输出

**核心原则：根据用户问题动态调整信息优先级，按需展示，避免信息过载。**

##### 5.1 信息优先级判断

根据问题类型，信息重要性排序如下：

| 问题类型 | 高优先级 | 中优先级 | 低优先级（可折叠） |
|----------|----------|----------|-------------------|
| **搜索视频** | 标题、UP主、时长、观看状态 | 收藏夹、播放量、简介前50字 | 完整简介、UP主简介、详细统计 |
| **技术问题** | 标题、简介关键词、UP主 | 时长、收藏夹、弹幕数 | 完整统计、UP主简介 |
| **UP主查询** | UP主名称、UP主简介、收藏数 | 视频标题列表 | 详细统计、视频简介 |
| **学习路线** | 标题、时长、收藏夹 | UP主、观看状态 | 简介、统计 |
| **数据统计** | 播放量、收藏数、点赞数 | 投币、分享、弹幕 | 简介、UP主信息 |

## 关注UP主查询流程

### 步骤详解

#### 1. 验证触发条件

检查问题是否包含 `关注`、`UP主` 关键词。

#### 2. 分层索引导航

- 读取 `knowledge/followings/data_structure.md`
- 了解关注列表统计和分布

#### 3. 检索策略

| 问题类型 | 检索方式 |
|----------|----------|
| "我关注了多少UP主" | 读取索引统计 |
| "我关注的xxx UP主" | grep 搜索UP主名称 |
| "我关注中有没有做xxx的" | grep 搜索简介关键词 |
| "我关注的UP主列表" | 按粉丝数排序输出 |

#### 4. 关联检索（重要）

**当查询特定UP主时，必须同时检索收藏中该UP主的视频**：

```
========================================
📋 执行计划
========================================
1. [验证] 检查触发条件 → ✅ 包含"关注"关键词
2. [导航] 读取 followings/data_structure.md 了解关注列表
3. [检索] 搜索匹配的UP主
4. [关联] 检索收藏中该UP主的视频
5. [输出] 结构化展示UP主信息 + 收藏视频
========================================
```

**关联检索实现**：
```bash
# 第一步：找到UP主
grep -l "UP主名称" knowledge/followings/*.md

# 第二步：在收藏视频中搜索该UP主
grep -l "UP主名称" knowledge/videos/*.md
```

## 特殊场景处理

### 初始化/同步请求

当用户请求"初始化"或"同步"B站收藏时：

```
========================================
📋 执行计划
========================================
1. [检查] 验证 config.json 中 Cookie 是否有效
2. [获取] 调用 B站 API 获取收藏夹列表
3. [同步] 获取每个收藏夹内的视频信息
4. [生成] 创建 knowledge/ 文档目录
========================================
```

**AI 自动执行**：
- 用户说"同步B站收藏" → AI 执行 `scripts/sync.py`
- 用户说"验证Cookie" → AI 执行 `scripts/login.py --check`
- 执行完成后展示结果摘要

### Cookie 过期处理

**Cookie 有效期约 30 天，过期后需要更新。**

当同步失败提示 Cookie 无效时，输出友好提示：

```
==================================================
[ERROR] 同步失败
==================================================

错误类型: Cookie 已过期

可能原因:
  1. Cookie 有效期约 30 天，已自然过期
  2. 账号在其他设备登录导致 Cookie 失效
  3. 修改密码或退出登录

解决步骤:
  步骤一：重新获取 Cookie
    1. 打开浏览器，访问 bilibili.com
    2. 登录你的账号
    3. 按 F12 → Network → 刷新页面
    4. 点击请求 → Headers → Cookie
    5. 复制整行 Cookie

  步骤二：更新配置
    运行: python scripts/login.py
    按提示粘贴新 Cookie

  步骤三：验证成功
    运行: python scripts/login.py --check

更多帮助: docs/troubleshooting.md
==================================================
```

**触发条件**：
- API 返回 `-101` 错误码（账号未登录）
- 验证 Cookie 时返回无效
- 同步过程中连续请求失败

## 回答风格

### ✅ 推荐做法

- 先输出执行步骤，再给出结果
- 用用户提问的语言作答
- 先给结论，再列依据
- 指明来源文件和位置

### ❌ 禁止行为

- ❌ 不验证触发条件直接执行
- ❌ 使用单一宽泛关键词搜索
- ❌ 返回无关分类的内容
- ❌ 臆造不存在的视频信息
- ❌ 满屏输出所有匹配结果（超过 20 条时分页）

## 故障排查

| 错误 | 原因 | 解决方案 |
|------|------|----------|
| HTTP 412 | 触发反爬 | 等待30分钟后重试 |
| Cookie无效 | 已过期 | 运行 `python scripts/login.py` 更新 |
| 无数据 | 未同步 | 运行 `python scripts/sync.py` 初始化 |
| 结果太多 | 关键词太宽 | 建议用户提供更具体关键词 |

详见：`docs/troubleshooting.md`
